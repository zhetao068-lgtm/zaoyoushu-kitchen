# 无账号菜谱网页的本机存储与发布包校验

灶有数工程论文 · 2026 年 11 月 16 日

## 摘要

本实验验证一个内嵌 1,286 道菜谱的单文件网页。公开发布物包括静态菜谱和浏览器程序。个人库存由使用者输入后写入浏览器存储。构建校验重算了 11 段脚本与 1 段样式的 SHA-256，全部与网页内容安全策略声明一致。浏览器验证在手机宽度下完成了搜菜、查看做法、录入库存和刷新后读取。 [发布包校验数据](../bench/release-audit.json)

## 数据流与设计

网页在进入时加载随发布包附带的菜谱。搜菜和库存匹配在浏览器进程中计算。要记住库存，应用调用 `localStorage`，并用同一键读回先前记录。使用同一浏览器的同一 HTTPS 来源时，这些记录可供下次使用。新域名、新浏览器或已清除的站点存储从空库存开始。使用本地文件时，持久化也取决于浏览器对文件来源的处理。 [WHATWG Web Storage](https://html.spec.whatwg.org/multipage/webstorage.html)

内容安全策略默认拒绝资源加载，并为发布时写入的脚本和样式配置 SHA-256 许可。`connect-src 'none'` 限制网页脚本发起连接，`form-action 'none'` 禁止通过表单导航提交。Trusted Types 在支持它的浏览器中约束接收脚本或 HTML 的 DOM 接口。用户自己点开的菜谱出处仍由其浏览器接收导航。 [W3C 内容安全策略](https://www.w3.org/TR/CSP3/) · [W3C Trusted Types](https://www.w3.org/TR/trusted-types/)

## 校验结果

| 指标 | 结果 |
| --- | ---: |
| 单文件 HTML 字节数 | 2,212,699 |
| gzip 压缩后字节数，级别 9 | 480,725 |
| 与策略吻合的内嵌脚本哈希 | 11 |
| 与策略吻合的内嵌样式哈希 | 1 |
| 单独核对出处和许可的扩充菜谱 | 877 |

最小浏览器流程从一个全新的 320 或 390 像素宽浏览器上下文开始。打开页面后搜索「三姜汤」，查看材料、步骤与来源，再录入「鸡蛋 4 个 土豆半斤」。刷新后读回鸡蛋 4 个和土豆 250 克，另开一个干净上下文时库存为空。验证使用合成库存，不涉及真实家庭数据。

gzip 指标描述发布物的可压缩程度。线上传输大小取决于托管方的响应编码。这个校验覆盖公开文件的资源来源、内容哈希和本机存储路径。站点托管日志、浏览器本身的安全性和终端数据备份属于另行验证的范围。

## 复现

运行 `node bench/audit-release.mjs`。脚本读取 `index.html`，重算内嵌资源哈希，核对发布包中没有公开管理员入口或私有服务配置，并报告扩充菜谱的许可分类。手机布局可通过浏览器的响应式模式复核。
